# Инфраструктура

## Программа

tgsweep работает на компьютере пользователя, сервера у него нет. Ставят его с PyPI через uv, Git у пользователя не нужен:

```sh
uv tool install tgsweep
```

Обновление: `uv tool upgrade tgsweep`. Страница пакета: https://pypi.org/project/tgsweep/. `uv tool install` выбирает версии зависимостей по диапазонам из `pyproject.toml`, а не по `uv.lock`, поэтому у каждой зависимости есть верхняя граница: новая мажорная версия библиотеки (у questionary и prompt-toolkit даже минорная) не попадёт в установки, пока на ней не прогнаны тесты. Границы поднимаются руками. Dependabot (`.github/dependabot.yml`) раз в неделю предлагает обновления uv и GitHub Actions; новую версию он берёт не раньше чем через 7 дней после выхода.

tgctl ставит tgsweep по своему тегу, выпуски на PyPI и push в main его не задевают.

### Выпуск версии

На PyPI пакет выкладывает `.github/workflows/release.yml` через trusted publishing: паролей и токенов PyPI в секретах репозитория нет. PyPI доверяет запуску по имени файла и окружения: проект tgsweep, владелец umbrella-at, репозиторий tgsweep, workflow `release.yml`, окружение `pypi`. Если переименовать файл или окружение, публикация перестанет проходить, пока издателя на PyPI не поправить так же.

1. Поднять версию в `pyproject.toml` и `src/tgsweep/__init__.py`, выполнить `uv lock`.
2. В `CHANGELOG.md` переименовать раздел `## [Unreleased]` в `## [X.Y.Z] - ГГГГ-ММ-ДД` (если его нет, добавить такой раздел в начало) и поправить ссылки сравнения внизу файла. Между выпусками изменения копятся в `[Unreleased]`: он может стоять только первым, версию `test_static` и `scripts/release.py check` сверяют с первым разделом, у которого есть номер.
3. Коммит, push, CI зелёный.
4. Тег `vX.Y.Z` на этот коммит и push тега. release.yml сверяет тег с версией и разделом CHANGELOG (`scripts/release.py check`), гоняет тесты, собирает пакет (`uv build`), проверяет его `twine check --strict` и состав wheel: только пакет tgsweep и метаданные.
5. Публикация ждёт подтверждения в окружении `pypi` (Settings, Environments; подтверждает umbrella-at; запуск разрешён только с тегов `v*`, с веток окружение его не примет): в запуске Actions нажать Review deployments, отметить pypi, Approve and deploy. После публикации тот же запуск создаёт GitHub Release по тегу с разделом CHANGELOG и файлами из `dist/`.

Файлы версии PyPI принимает один раз: загрузить их заново нельзя даже после удаления. Если что-то не так после публикации, исправление уходит следующей версией. Если запуск упал до публикации, можно поправить коммит, удалить тег и поставить его заново.

### Установка из main.zip

До 0.3.0 (27.11.2026) сайт и README ставили программу из архива ветки main. Так по-прежнему можно поставить непроверенную сборку, то, что уже лежит в main, но ещё не выпущено:

```sh
uv tool install --force https://github.com/umbrella-at/tgsweep/archive/refs/heads/main.zip
```

`uv tool upgrade tgsweep` такую установку не обновляет: у ответа GitHub нет заголовков кэширования, uv берёт архив из своего кэша и пишет «Nothing to upgrade» (проверено на uv 0.12.5, 2026-11-27). Свежий main ставит только `uv tool install --reinstall` с тем же адресом.

Вернуться на PyPI: `uv tool install --force tgsweep`. Проверено на uv 0.13.10 (2026-11-27): после неё `uv tool list` показывает версию с PyPI, и дальше работает `uv tool upgrade tgsweep`. Без `--force` uv только запоминает новый источник, а установленная из архива версия остаётся до следующего upgrade.

## Сайт tgsweep.atworks.dev

- Исходники: папка `site/`, статические HTML, CSS, JS и шрифты. Сборки нет, файлы уходят как есть.
- Страниц две: русская `site/index.html` (адрес /) и английская `site/en/index.html` (адрес /en/). Они связаны тегами `link rel="alternate" hreflang` (x-default ведёт на английскую) и переключателем языка последним пунктом в шапке. Разметка у них одна и та же, отличаются только тексты: правку вёрстки делать в обеих, `test_static` сверяет набор id, шаги, команды и блоки по системам. На английской странице пути к файлам абсолютные (`/style.css`, `/app.js`, `/fonts/...`), на русской относительные. Caddy отдаёт /en/ как `en/index.html` и сам перенаправляет /en на /en/.
- Язык страницы выбирает `site/lang.js`. Он подключён в `<head>` обеих страниц без defer и async, раньше шрифтов и стилей, поэтому переход случается до отрисовки. Если открыта страница не того языка, скрипт делает `location.replace` на другую (`/` или `/en/`), сохраняя query и hash; «Назад» на брошенную страницу не возвращает. Нужный язык: ручной выбор, если он сохранён, иначе первый из `navigator.languages` с кодом ru или en, иначе en. Клик по ссылке языка в шапке запоминает выбор в localStorage под ключом `tgsweep-lang` (рядом лежит `tgsweep-os`, выбранная система). Cookies нет, на сервер выбор не уходит. Скрипт не трогает роботов (`/bot|crawl|spider|slurp|facebookexternalhit/i`) и тех, кто пришёл со страницы этого же сайта. Слова telegram в списке роботов нет намеренно: встроенный браузер Telegram на Android пишет в user agent Telegram-Android, а превью ссылок ходит как TelegramBot, его ловит bot. Если хранилище недоступно, скрипт работает без памяти и без ошибок. После перехода браузер считает источником сам сайт, поэтому перед `location.replace` скрипт кладёт настоящий referrer в sessionStorage под ключом `tgsweep-ref` (целиком, как его дал браузер; пустую строку, если referrer не было). Новая страница читает ключ, сразу удаляет его и отдаёт значение счётчику через его настройку `window.goatcounter.referrer` (https://www.goatcounter.com/help/js), раньше, чем загрузится count.js в конце `<body>`. Адрес после перехода остаётся тем же, что пришёл, без добавленных параметров: ссылка, скопированная после перехода, не несёт чужого источника. GoatCounter видит такой заход как обычный переход по ссылке и показывает его одной строкой с остальными. Если sessionStorage недоступен, переход работает, но источником будет сам сайт. Сбросить выбор: в консоли браузера на сайте `localStorage.removeItem("tgsweep-lang")`. CSP для этого не менялась: файл свой, `script-src 'self'` его пропускает; встроенный скрипт потребовал бы хэш в трёх местах (заголовок в `deploy/tgsweep.caddy` и meta обеих страниц). `test_static` проверяет место и вид подключения, неизменную CSP и список роботов.
- `site/app.js` общий для обеих страниц. Тексты демо и кнопок копирования лежат в каждой странице в блоке `<script type="application/json" id="page-text">` перед счётчиком GoatCounter, формы слов app.js выбирает по `lang` страницы. CSP такой блок не исполняет и не блокирует.
- Хостинг: forester (77.90.43.37), общий Caddy хоста. Сайт описан в `/etc/caddy/sites/tgsweep.caddy`: статика из `/var/www/tgsweep/current`, сжатие, заголовки безопасности и CSP. Журнала доступа нет намеренно: он хранил бы IP посетителей, а сайт обещает не собирать личные данные.
- Копия файла сайта лежит в `deploy/tgsweep.caddy` и ставится на сервер руками, деплой её не трогает. Правка: скопировать файл, `runuser -u caddy -- caddy validate --config /etc/caddy/Caddyfile`, затем `systemctl reload caddy` (не restart). Reload только при пустой очереди загрузок страницы съёмки daim, правила хоста в `/etc/caddy/README-sites.md` на forester.
- Деплой: `scripts/deploy-site.sh` с компьютера, где есть ssh-доступ к forester (Host forester в `~/.ssh/config`). Скрипт кладёт `site/` в новую папку `/var/www/tgsweep/releases/<время>` и одним шагом переключает на неё ссылку `current`; хранятся три последних выпуска. Reload Caddy для этого не нужен. Push в main сайт не выкладывает.
- Откат: на forester `cd /var/www/tgsweep && ln -sfn releases/<прошлый выпуск> current.new && mv -Tf current.new current`.
- Домен: в Cloudflare, зона atworks.dev, запись A `tgsweep` на 77.90.43.37 с выключенным прокси (серое облако, DNS only), как у остальных сайтов forester. Сертификат Let's Encrypt Caddy получает и продлевает сам.
- Проверка перед деплоем: `python3 -m http.server -d site 8000` и открыть http://127.0.0.1:8000 и http://127.0.0.1:8000/en/. Через file:// страница откроется без шрифтов: их не пропускает CSP.
- CSP задана дважды: заголовком в `deploy/tgsweep.caddy` (там же запрет встраивать страницу в чужие сайты) и тегом meta в обеих страницах, `site/index.html` и `site/en/index.html`; тег должен быть одинаковым. Скрипты только свои и с gc.zgo.at, отправка данных только на *.goatcounter.com.
- Статистика: GoatCounter, сайт umbrella.goatcounter.com, без cookies. Подпись в подвале сайта перечисляет то, что он записывает по умолчанию: просмотры, источник перехода, браузер, система, страна, ширина экрана. Если в его настройках (Settings, Data collection) включить что-то сверх этого, подпись надо дополнить; если отключить, её можно сократить. Код счётчика стоит в обеих страницах перед `</body>`.
- Шрифты Golos Text и JetBrains Mono (OFL 1.1) лежат в `site/fonts/` вместе с лицензиями. Они урезаны до латиницы, кириллицы и символов терминала, поэтому весят 44 и 20 КБ.
- Экраны терминала на странице сняты с настоящей программы на выдуманном аккаунте из `tests/fake.py`. На английской странице они собраны из английских строк программы (`src/tgsweep/i18n.py`) с теми же числами. Если меняются тексты программы, экраны надо переснять на обеих страницах; `test_site_mockups_match_program` сверяет их с программой для каждого языка.
- Превью ссылок для Telegram: `site/og.png` у русской страницы и `site/og-en.png` у английской, 1200 на 630. Обе собираются из одного шаблона `scripts/og.html` (язык выбирает атрибут lang) командой `uv run scripts/render-og.py`: Playwright берётся только для этого скрипта, рисует установленный Google Chrome, скрипт останавливается, если не загрузились шрифты сайта. После правки текста или цветов картинки надо пересобрать и закоммитить.
- Палитра: цвета Telegram, вариант «Как в приложении». Все цвета сайта заданы токенами в начале `site/style.css`: светлая тема в `:root`, тёмная в двух одинаковых блоках, `@media (prefers-color-scheme: dark)` и `:root[data-theme="dark"]`. Фирменный голубой Telegram #2AABEE остаётся только в значке (`--mark`): белый текст на нём даёт контраст 2.57, поэтому кнопки и ссылки идут цветом `--accent`. Вместе с токенами перекрашиваются места, которые CSS-переменные прочитать не могут: `site/favicon.svg` (`--mark` и `--mark-in`), `meta name="theme-color"` на обеих страницах (`--bg` светлой и тёмной темы, цвет адресной строки на телефоне), образец QR-кода на обеих страницах (модули цветом `--t-bg`), шаблон превью `scripts/og.html` (токены светлой темы под теми же именами) и записи терминала `docs/media/demo-*.tape` (`MarginFill` равен `--bg`, `background` и `foreground` темы равны `--t-bg` и `--t-fg`). После смены палитры превью и записи надо пересобрать. `tests/test_palette.py` сверяет эти места с токенами, проверяет контраст пар по WCAG 2.1 в обеих темах и не пускает обратно цвета прежней зелёной палитры.
- `tests/test_static.py` проверяет, что обе страницы и оба README (`README.md` английский, `README.ru.md` русский) дают одни и те же команды установки и что в текстах сайта и README нет длинных и коротких тире.

## Записи работы программы в README

- В начале `README.md` и `README.ru.md` стоят записи терминала: `docs/media/demo-en.gif` и `docs/media/demo-ru.gif`. Сценарии VHS (charmbracelet/vhs) лежат рядом: `docs/media/demo-en.tape` и `docs/media/demo-ru.tape`. В архив main.zip папка `docs/media` не попадает: `.gitattributes` помечает её `export-ignore`. В пакет на PyPI она не попадает тоже: в wheel идёт только `src/tgsweep`. README на GitHub и на PyPI показывает записи по абсолютным адресам raw.githubusercontent.com.
- Записывается настоящая программа (`cli.run`, `sweep`, вопросы в терминале) на выдуманном аккаунте. `scripts/demo.py en` или `ru` собирает мир Марии на `FakeClient` из `tests/fake.py` (те же чаты и числа, что на сайте), берёт временную папку программы и выдуманные api_id и api_hash. Сети нет: фабрика клиентов отдаёт только `FakeClient`. Паузы сокращены в самом скрипте: ответы `FakeClient` идут с небольшими задержками, паузы между запросами удаления в 10 раз короче настоящих. Код программы ради записи не меняется.
- Пересобирать, когда меняются тексты или ход программы (вопросы, строки поиска и итога) или числа демо-мира. `tests/test_demo.py` прогоняет мир через программу и сверяет числа записи: если он падает, записи устарели.
- Нужны vhs (`brew install vhs`, он ставит ttyd и ffmpeg) и шрифт JetBrains Mono (`brew install --cask font-jetbrains-mono`); проверено на vhs 0.12.1. Из корня репозитория:

```sh
mkdir -p docs/media/check
vhs docs/media/demo-en.tape
vhs docs/media/demo-ru.tape
```

- Каждая запись идёт около 25 секунд и весит около 0,6 МБ; `tests/test_demo.py` не пропускает GIF больше 3 МБ. Если выйдет больше, снизить `Set Framerate` в сценарии или сжать `gifsicle -O3 --lossy=30`, проверив, что текст остался чётким.
- Кроме GIF сценарий пишет в `docs/media/check/` текст всех экранов (`demo-en.txt`, `demo-ru.txt`) и по четыре контрольных кадра: после поиска, выбор чатов, подтверждение, финал. Папка в `.gitignore`: это для проверки глазами, в репозиторий она не идёт.
